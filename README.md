# Dual-Backbone Graph Fusion Network for Chalcohalides

This repository contains the code, processed data manifests, fold splits, and exported results used for the dual-backbone graph fusion model reported in the AgBiSeCl2 chalcohalide screening manuscript.

The reporting model is the MACE+ALIGNN dual-backbone fusion network. It combines a MACE-MP-0 small representation with an ALIGNN-style crystal/line-graph representation and jointly predicts band gap, band-gap type, and thermodynamic stability.

## Repository Layout

- `multitask/`: model definitions, PyTorch/PyG datasets, training scripts, and analysis utilities.
- `scripts/`: screening, prediction, plotting, and dataset construction utilities.
- `slurm/dual_backbone_inorg.slurm`: portable Slurm template for five-fold dual-backbone retraining.
- `Data/Inorganic_datasets/`: processed labels, atom features, and aligned five-fold split files.
- `Data/cifs_chalcohalide/`: CIF structures for the chalcohalide training set.
- `export_splits/`: reviewer-readable train/validation/test split exports.
- `results/best_bg_six_model_figures/`: exported out-of-fold predictions and figure source data for the six-model comparison.
- `exports/`: screening manifests, traditional-ML exports, and candidate CIF archives.
- `MODEL_STATUS.md`: official reporting checkpoint provenance and metric summary.

Large generated graph caches and trained checkpoint files are not committed. They are reproducible from the included CIFs, labels, split files, and training scripts, but they are too large for a normal Git repository.

## Quick Reproduction From Exported Results

Use this route to verify the manuscript tables and plots without retraining GPU models.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m compileall multitask scripts classical_ml_baseline
```

Key exported files:

- Six-model out-of-fold predictions: `results/best_bg_six_model_figures/six_model_oof_predictions_best_bg_mace_alignn.csv`
- Six-model fold metrics: `results/best_bg_six_model_figures/six_model_fold_metrics_best_bg_mace_alignn.csv`

- 12,018-compound screening manifest: `Data/predict_final_main6_manifest.csv`
- 453 final candidate manifest: `exports/final_candidates_screen_direct_stable_bg_0p5_1p1/final_candidates_453_manifest.csv`

## Full GPU Reproduction

Set the repository root on `PYTHONPATH` and use the included split files.

```bash
export PROJECT_ROOT=$PWD
export PYTHONPATH=$PROJECT_ROOT/multitask:$PYTHONPATH
export DATA=$PROJECT_ROOT/Data/Inorganic_datasets
```

The dual-backbone training script expects:

- `Data/Inorganic_datasets/id_prop.csv`
- `Data/Inorganic_datasets/*.cif` or cache files generated from those CIFs
- `Data/Inorganic_datasets/mace_cached_graphs/`
- `Data/Inorganic_datasets/crystal_cached_graphs/`
- a MACE pretraining checkpoint at `checkpoints/mace_pretrain/pretrained_best.pt`
- fold-specific ALIGNN checkpoints at `checkpoints/alignn_mt_inorg/fold{0..4}_best.pt`

MACE and crystal graph caches are generated by the dataset loaders during backbone training when the cache directories are missing. For a Slurm array run, adapt:

```bash
mkdir -p logs checkpoints
sbatch slurm/dual_backbone_inorg.slurm
```

Local single-fold command:

```bash
python multitask/train_dual_backbone.py "$DATA" \
  --mace-cache-dir "$DATA/mace_cached_graphs" \
  --crystal-cache-dir "$DATA/crystal_cached_graphs" \
  --checkpoint-dir checkpoints/dual_backbone_inorg \
  --mace-pretrained checkpoints/mace_pretrain/pretrained_best.pt \
  --alignn-checkpoint-dir checkpoints/alignn_mt_inorg \
  --fold 0 --k-folds 5 --seed 42 \
  --mace-model small --epochs 300 --batch-size 32 --workers 4
```

Inference on new CIFs after retraining:

```bash
python scripts/predict_inorg_dual_backbone.py path/to/cifs predictions.csv \
  --checkpoint-dir checkpoints/dual_backbone_inorg \
  --alignn-checkpoint-dir checkpoints/alignn_mt_inorg \
  --device cuda
```

## Data Availability Notes

The Materials Project-derived training structures are distributed here as CIF files and processed labels for reproducibility. Large intermediate graph caches and model weights are intentionally excluded. See `DATA_MANIFEST.md` for file-level details and `REPRODUCIBILITY.md` for the reviewer workflow.
